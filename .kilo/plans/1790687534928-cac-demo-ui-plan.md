# CAC Interactive Demo UI — Ultra-Detailed Phased Plan

**Target:** a judge-facing, web-based, interactive demo built by **extending the existing Streamlit app** (`app/`).
**Audience:** a non-expert judge ("a dummy") who must *get it in 60 seconds* and a skeptical judge who will *try to break it*.
**One sentence the whole demo must land:** *"Every method can flip the model on paper, but only a plan that also survives the causal model and a real person could actually do is usable — and CAC is the only one that is usable every time."*

## 1. Architecture decision (locked)

**Extend the existing Streamlit app.** No new web framework, no new runtime deps. Convert the single-page `app/app.py` into a **multipage app via `st.navigation` + `st.Page`** with explicit ordering, icons, and a shared sidebar. Every page is a thin function that calls the already-tested `components`/`live` layer.

### New file layout (all under `app/`)
```
app/
  app.py            # entrypoint: page config, st.navigation, global state, preflight, demo-mode toggle
  components.py     # (existing, keep) + a few additive helpers
  live.py           # (existing, keep) + a few additive helpers
  ui/               # NEW package — one module per page + shared widgets
    __init__.py
    state.py        # session_state keys, dataset/applicant pickers, demo-mode, theme constants
    theme.py        # plain-language strings, badge/HTML helpers, big-font CSS for demo mode
    page_home.py    # Phase 1 — The Problem (hook)
    page_gap.py     # Phase 2 — The Gap (population)
    page_applicant.py  # Phase 3 — Head-to-head (per applicant)
    page_sandbox.py    # Phase 4 — Live Sandbox (the star)
    page_map.py     # Phase 5 — The Causal Map
    page_evidence.py   # Phase 6 — Is this real? (significance/robustness/ablation)
  assets/           # optional: a small glossary.md, tour steps
.streamlit/
  config.toml       # NEW — demo theme (brand colours, wide layout, font)
```
Keep `app/components.py` and `app/live.py` public functions intact so `scratch/smoke_app.py` and any tests keep passing; only **add** helpers.

## 2. Cross-cutting foundations (build in Phase 0, used everywhere)

- **Shared state (`ui/state.py`):** `st.session_state` keys `dataset`, `record`, `demo_mode`, `sandbox_edits`, `seeded_from`. One sidebar dataset picker + applicant picker reused by every page so context follows the judge across pages.
- **Preflight guard:** on entry, detect what is available:
  - results-only pages need `results/*.csv` (via `components.load_csv`);
  - live pages need `models/` + `data/processed/` (via `live.datasets_live()`).
  Show a single friendly banner if something is missing ("Run `make all` first") and **disable** (not crash) the pages that need it.
- **Caching discipline:** `@st.cache_resource` for `get_engine`/models/SCM; `@st.cache_data` for CSVs, generated plans, cohort tables. Add a **warm-up** on first load (Phase 7) so the first live interaction isn't slow in front of the judge.
- **Plain-language layer (`ui/theme.py`):** every technical term gets a fixed one-line gloss. F/S/A rendered as three coloured chips everywhere: **F = "Flips the decision"**, **S = "Survives real-world knock-on effects"**, **A = "A real person could actually do it"**, then **Usable = all three**. Reuse `verdict_markdown` styling; extend to large "demo mode" variant.
- **Demo mode toggle:** sidebar switch → injects big-font CSS, hides developer captions, expands charts. Lets the same app serve both a projector demo and a detailed walk-through.

## 3. The judge journey (how phases map to the demo story)

1. **Home** — "Here is one rejected person. Here is the advice a normal tool gives. It's impossible / it backfires." (emotional hook, 30s)
2. **The Gap** — "Zoom out: across everyone, every tool flips the model, but look how few plans are actually usable — 13% for one tool. CAC: 100%." (the thesis, 45s)
3. **Head-to-head** — "Pick anyone. Watch each tool's advice pass or fail the three tests, side by side." (proof per case)
4. **Live Sandbox** — "You drive. Type any plan. Watch the causal model reveal the hidden knock-on effects and re-score it live." (the wow / interactivity)
5. **Causal Map** — "This is the world-model doing the judging. Change one thing, see what it drags along." (mechanism)
6. **Is this real?** — "Not cherry-picked: confidence intervals, significance tests, works under a wrong graph, works on a different model, and turning off the causal term brings the gap right back." (skeptic killer)

Navigation order in `st.navigation` follows this exactly; icons: 🏠 📊 ⚖️ 🎛️ 🕸️ 🔬.

### Phase 1 — Home / "The Problem" (the hook)
**Goal:** in 30 seconds, a non-expert feels the problem: standard recourse advice can be impossible or self-defeating.

**Build**
1. `ui/page_home.py`: one big headline, the plain-language F/S/A explainer (three chips + one sentence each), and a **single concrete rejected applicant** rendered as a human story.
2. Pull one curated case from `results/qualitative_cases.csv` (prefer HELOC or a case tagged `immutable_advice` / `cheaper_but_wrong`); show:
   - the applicant in human terms (`LiveEngine.decode` + `pretty`),
   - "A typical tool says: *do X*" (a baseline plan's `advice`),
   - "But that plan **fails** because …" (its failing chip: not-actionable or breaks-causal),
   - "CAC says: *do Y*, and it holds." (cac `advice` + `consequences` text).
3. A prominent **"See the whole picture →"** button that navigates to The Gap.

**Visual data**
- Three F/S/A chips with plain text.
- A before→after mini table for one applicant (feature, now, asked) via `moves_table` / `plan_frame`.
- Big verdict badges (CAC = USABLE green; baseline = not usable red) using `verdict_markdown` large variant.

**Judge edge-cases**
- *"Is this one hand-picked example?"* → explicit "one example; next page is the whole population."
- *"What does 'survives the causal model' even mean?"* → the gloss + a one-line concrete phrasing ("asking for a higher balance forces years of history you don't have").
- *"Where do these numbers come from?"* → caption: read from stored `results/`, model never re-queried here.

**Data sources:** `results/qualitative_cases.csv` (`advice`,`consequences`,`valid`,`causal`,`actionable`,`usable`,`cost`), `LiveEngine.decode/pretty` for readability.

**Acceptance:** loads instantly (results-only), one CAC-usable vs one baseline-failing story visible without scrolling on a projector, works for at least HELOC + Adult.

### Phase 2 — The Gap (population evidence)
**Goal:** the thesis chart. Everyone clears validity; usable ranges 13%→100%; CAC closes it.

**Build**
1. `ui/page_gap.py`: reuse `components.gap_figure(headline, dataset)` (faint=validity, solid=usable) as the hero chart.
2. Add a **F→S→A→Usable funnel** for the selected dataset: four descending bars (validity, causal_validity, actionability, usable) per method, so the judge sees *which* test each method fails. New small matplotlib helper `funnel_figure(headline, dataset)` in `components.py` using `method_colour`.
3. Headline metric row: `st.metric` for "CAC usable" (always 100%) vs "Worst baseline usable" (e.g. HELOC Wachter 13%) with the delta.
4. Dataset switcher prominent at top (not just sidebar) so the judge can flip HELOC→Adult live.
5. "How to read this" panel (reuse existing copy from `app.py:_gap`).

**Visual data**
- Gap bar chart (per method: validity vs usable).
- F/S/A/Usable funnel (per method).
- Two big metrics: CAC usable, worst-baseline usable, and the gap between them.

**Judge edge-cases**
- *"Cherry-picked dataset?"* → switcher shows all four; **Adult deliberately shows a small gap** (honest). Add a caption: "On Adult the problem is mild; on HELOC it's severe — we show both."
- *"What's the difference between validity and usable?"* → the funnel literally decomposes it.
- *"Is 100% suspicious / overfit?"* → link/anchor to Evidence page (significance + CI); caption "per-record over 100 held-out applicants, 5-seed CI on the Evidence page."
- *"Why is oracle not 100%?"* → tooltip: the cost-oracle ignores causal consistency, so it fails S on some records (Adult oracle causal_validity 0.87).

**Data sources:** `results/headline.csv` (`validity`,`causal_validity`,`actionability`,`usable`,`cost_mean`,`n_records`).

**Acceptance:** switching dataset re-renders both charts + metrics; HELOC shows the dramatic 13→100 story; funnel bars are monotone non-increasing F≥S? (note: order is F, then S and A independently, then Usable = min-of-conjunction) and correctly show where each baseline drops.

### Phase 3 — Head-to-head (per applicant)
**Goal:** for any single applicant, show each method's advice side by side and which of the three tests it survives. This is the enhanced version of the current `_applicant` view.

**Build**
1. `ui/page_applicant.py`: applicant picker (curated case **or** any rejected record) reusing `app.py:_sidebar` logic; move it into `ui/state.py`.
2. Hero image: `components.recourse_png(ds, record, frame)` (side-by-side per-method plans; solid=asked, hatched=SCM-added, ringed=audit failed).
3. **Per-method verdict cards** (replace the current flat list): one card per method with the three F/S/A chips, the Usable badge, the effort/cost, and an expander with:
   - `moves_table(row)` — what the plan asked vs what the SCM makes follow,
   - the failing reason in words (e.g. "asks to change *age* — nobody can" from `blocked_features`; or "breaks causal: forces *X*" from `off_features`).
4. For curated cases, keep the CAC narrative block (`advice`/`consequences`).
5. Sort cards CAC-first (reuse `methods_for`).

**Visual data**
- Side-by-side recourse plan figure.
- Per-method cards: F/S/A chips + Usable badge + cost + moves/consequences tables.
- Optional cost comparison bar (cost per method for this applicant).

**Judge edge-cases**
- *"Isn't CAC just spending more effort to win?"* → show cost per method; on many records CAC is competitive; where a baseline is *cheaper*, it's because it's *wrong* — surface `cost_ratio` and the failing chip (use a curated `cheaper_but_wrong` case).

- *"Does CAC ever fail?"* → be honest: browse records; if none fail on a dataset say so; point to the datasets where oracle/baselines fail on S.
- *"What are 'side effects'?"* → the consequences table with the SCM-added rows highlighted.

**Data sources:** `components.per_record(ds)` (joins `counterfactuals.csv` + `feasibility_per_cf.csv` + `faithfulness_per_cf.csv`), `qualitative_cases.csv`, `recourse_png`.

**Acceptance:** any rejected record renders a figure + one card per available method; at least one curated case per dataset (where present) shows a baseline failing S or A with a plain-language reason; CAC always first.

### Phase 4 — Live Sandbox (the star / real interactivity)
**Goal:** the judge drives. Type or drag a plan for a real applicant and watch the three audits recompute live, including the hidden causal knock-on effects. This is where "web-based interactive" pays off, powered by the already-built `LiveEngine`.

**Build**
1. `ui/page_sandbox.py`: pick a rejected applicant (`live.rejected_records`), load `eng = get_engine(ds)`, `x = eng.factual_row(record)`, `meta = eng.feature_meta(x)`.
2. **Editors per feature** from `meta`:
   - categorical/ordinal → `st.select_slider`/`selectbox` over `levels`;
   - numeric → `st.slider` with `[lo, hi]`, integer step when `integer`;
   - **immutable** features → render **disabled/locked** with a lock icon and tooltip "cannot be changed";
   - mark **sensitive** features visually (they're allowed to move but flagged).
3. Assemble `x_edit`; call `eng.audit(x, x_edit)` (free-typed → `asked=None`, every edit is an action). Render live:
   - **Verdict banner**: three big F/S/A chips + Usable, from `Audit.valid/causal_valid/actionable/usable`.
   - **The reveal — SCM cascade table**: `eng.consequence_frame(audit)` → "you asked" vs "world result", with `breaks causal` rows highlighted red. This is the moment the hidden effects appear.
   - **Cost/effort meter**: `Audit.normalised` vs budget 1.0 (progress bar), `n_changed` vs `MAX_ACTIONS=3`, over-budget/over-actions warnings.
   - **Why not usable** panel: expands `Audit.off_features`, `violations`, over-budget/over-actions into plain sentences.
4. **Seed buttons**: "Start from CAC's plan" / "…from DiCE's plan" using `live.generate_plans` + `live.seed_from_plan` (seeds only the *asked* features so the SCM re-derives fallout live — shows what a non-causal tool hides).
5. **Reset to applicant** button; **Download verdict** (`Audit.as_dict()` as JSON).
6. Security/telemetry note in code + UI caption: engine only calls `predict_proba` (never trains, never mutates the box).

**Visual data**
- Live three-chip F/S/A + Usable verdict.
- SCM cascade table (asked vs world result; breaks-causal highlighted).
- Effort gauge (normalised cost vs 1.0) + action-count vs cap.
- Probability readout: `proba_target` before vs `proba_repaired_target` after the SCM fills in consequences.

**Judge edge-cases (this page is designed to be attacked)**
- *"Ask for something impossible"* → editing an immutable feature is locked; if seeded plan touches one, A=red with the feature named.
- *"Max everything out"* → over-budget and/or over-actions (>3) → A=red with explicit reason.
- *"I only changed one number — why did five others move?"* → the SCM cascade table is the answer; that's causal knock-on.
- *"Make a plan that flips the box but breaks causally"* → e.g. set a downstream feature inconsistent with its parents → F=green, S=red, off_features listed; **flip may not survive repair** (`flip_survives`).
- *"Can I make CAC's plan fail?"* → seed from CAC, then perturb; show it was usable and how tampering breaks it.
- *"Is it actually recomputing or faking it?"* → numbers change on every widget move; show the `proba_target` shifting; caption "one `predict_proba` + one SCM repair per change."
- *"What about the diabetes set that has fewer causal links?"* → `has_causal` guard; if a dataset lacked an SCM the cascade panel would say "no causal model"; all four have one, note nodes/edges.

**Data sources:** live only — `LiveEngine.audit`, `feature_meta`, `consequence_frame`, `generate_plans`, `seed_from_plan`. No CSV.

**Acceptance:** editing any mutable feature updates all three chips + cascade table within ~1s (after warm-up); immutable features are locked; an over-budget plan shows A=red with reasons; seeding from CAC reproduces a usable verdict; download returns valid JSON matching `Audit.as_dict()`.

### Phase 5 — The Causal Map
**Goal:** make the "world model" concrete and show visually that one action drags others along.

**Build**
1. `ui/page_map.py`: render the dataset SCM via `plot_graphs.plot_scm(get_scm(ds))` (nodes coloured by role: plain/immutable/sensitive/target).
2. **Intervention highlighter**: multiselect of `scm.manipulable` features → `plot_graphs.plot_intervention_paths(scm, actions)` highlights the chosen nodes and everything downstream (`scm.downstream(actions, include_target=True)`).
3. Link to sandbox: "act on these in the sandbox" prefills the same features.
4. Honesty panel: show `results/scm_validation_summary.csv` for the dataset (nodes, edges, DAG=yes, target reachable, edges supported e.g. HELOC 18/28) with a caption acknowledging imperfect graphs (German/HELOC) — pre-empts the "your graph is wrong" attack and hands off to Evidence/robustness.

**Visual data**
- SCM DAG figure with role legend.
- Highlighted intervention→cascade figure.
- SCM validation summary table (supported vs unsupported edges, independencies upheld).

**Judge edge-cases**
- *"How do you know the graph is right?"* → validation table is shown, and it's explicitly imperfect; robustness (Phase 6) shows CAC survives a wrong graph.
- *"Isn't this hand-drawn / arbitrary?"* → yes, hand-crafted domain graph, version-controlled JSON; supported-edge counts shown.
- *"What can actually be acted on?"* → manipulable vs immutable roles are colour-coded; multiselect only offers manipulable nodes.

**Data sources:** `get_scm(ds)`, `plot_graphs`, `results/scm_validation_summary.csv`.

**Acceptance:** DAG renders for all four datasets; selecting an action highlights its descendants and the target; validation table matches the CSV.

### Phase 6 — "Is this real?" (Evidence: significance · robustness · ablation)
**Goal:** dismantle the skeptical judge. Three tabs.

**Build** — `ui/page_evidence.py` with `st.tabs(["Significance","Robustness","Ablation"])`.

**Tab A — Significance (not luck):**
- CI bars per method from `results/significance_aggregate.csv` (`usable_mean` ± `usable_lo/hi`, 5 seeds).
- Paired tests table from `results/significance_tests.csv`: `usable_gap`, `[gap_lo,gap_hi]`, `mcnemar_p_holm`, `significant`. Highlight HELOC Wachter gap 0.854, p≈1e-128, significant.
- Plain caption: "each dot is a rate averaged over 5 seeds; whiskers are 95% CI; stars are Holm-corrected McNemar."

**Tab B — Robustness (works when things are wrong):**
- **Graph perturbation** from `results/robustness_headline.csv` (arm=scm) / `robustness_graphs.csv`: show CAC usable under `true` vs `drop1/drop2/add1` edges → "degrades gracefully" (Adult stays ~0.95–1.0).
- **Model transfer** from `results/robustness_model.csv`: CAC audited on XGB vs MLP still usable.
- **k and budget** sweeps (`robustness_k.csv`, `robustness_budget.csv`): usable vs number of suggestions / action cap.
- One line chart or small-multiples per sub-arm; captions in plain words.

**Tab C — Ablation (the causal term does the work):**
- From `results/ablation_headline.csv`: bar of `usable` for `cac` vs `cac_no_causal` per dataset. The headline: **drop the causal term and the gap reappears** — HELOC 1.00→0.68, Adult 1.00→0.85, German 1.00→0.94, Diabetes 1.00→0.977. Also show `causal_validity` and `flip_survival` columns to explain *why*.
- Caption: "remove causal scoring → plans stop surviving the world model → usable falls. That's the whole thesis, isolated."

**Visual data:** CI dot/bar charts, significance table, robustness line/bar small-multiples, ablation before/after bars.

**Judge edge-cases**
- *"Statistically significant?"* → McNemar + Holm, CIs.
- *"What if your causal graph is wrong?"* → graph-perturbation arm.
- *"Only works on your one model?"* → model-transfer arm (XGB→MLP).
- *"Is the causal part actually doing anything?"* → ablation: turning it off brings the gap back.
- *"Sensitive to k or budget?"* → the sweeps.

**Data sources:** `significance_aggregate.csv`, `significance_tests.csv`, `robustness_headline.csv`, `robustness_graphs.csv`, `robustness_model.csv`, `robustness_k.csv`, `robustness_budget.csv`, `ablation_headline.csv`.

**Acceptance:** each tab renders for the selected dataset; ablation clearly shows no_causal < cac; significance table flags HELOC/German/Diabetes as significant; charts use the shared palette.

**Acceptance:** cold start → interactive within a few seconds after warm-up; demo mode readable on a projector; no unhandled exception on any page when a dataset lacks live artifacts; golden path runs end to end.

## 6. Risks & mitigations
- **First-interaction latency (models load).** → Phase 7 warm-up + `cache_resource`; show a spinner with an honest "loading the model once" message.
- **Missing artifacts on the demo machine.** → Phase 0 preflight disables (not crashes) affected pages; results-only pages (Home, Gap, Evidence, Map-tables) work even without models.

### Gap A — The Home hook is empty on the **default** dataset (HIGH: it's the first thing the judge sees)

**Fix (choose 1a; 1b is the safety net).**
- **1a. **Acceptance.** Cold start (no stored session) shows a failing-baseline story with CAC-usable contrast without switching datasets; manually selecting adult still shows a coherent hook (via 1b) rather than the bare parenthetical.

### Gap B — Sandbox verdict contradicts the cascade caption (HIGH: hands a skeptic an easy hit)
**Symptom.** The three-chip verdict/`big_verdict` reads the **S** chip from `promise_kept = valid & flip_survives & causal_valid` (post-fix `audit_states`, `theme.py:73`). The cascade (`page_sandbox._cascade`, `page_sandbox.py:204–223`) decides its message purely from the `breaks causal` column (i.e. gap/`off_features`), **ignoring `flip_survives`**. So when a plan clears the SCM gap test but the repaired probability falls back below 0.5, the page simultaneously shows **S = red / NOT USABLE** and the green caption *"The world moved these features, but within tolerance — the flip still survives."*
**Verified reachable.** heloc, record 0, seed from `oracle` plan index 1: `valid=True, causal_valid=True, off_features=(), breaks_causal_any=False`, but `flip_survives=False` (`proba_target 0.520 → proba_repaired_target 0.315`, crossing 0.5), `promise_kept=False`. The `_verdict` metric already shows the 0.52→0.32 drop, so the contradiction is visible in one screenful.
**Fix (localized to `_cascade`).** Make the cascade message a function of **both** signals:
1. If `frame` non-empty and `broke` (a row breaks causal) → keep the existing red error.
2. Else if `not audit.flip_survives` → show a **red/warning** state: *"No single feature breaks the graph, but once the world reacts the model's confidence falls from {proba_target:.2f} to {proba_repaired_target:.2f} — back under the {DECISION_THRESHOLD:.0%} line — so the 'yes' does not survive."* (Pull threshold from `CONFIG.DECISION_THRESHOLD`.)
3. Else (`flip_survives` True, nothing broke) → the existing green "flip still survives" caption.
   Also gate the `frame.empty` green success at `page_sandbox.py:211–213` behind `audit.flip_survives` (a plan can change nothing downstream yet still be an invalid flip). When `frame.empty and not flip_survives`, show the same case-2 message.
**Acceptance.** For the heloc rec-0 oracle-plan[1] seed, the cascade no longer claims the flip survives; the S chip, the P(target)→P(repaired) metric, and the cascade caption all agree. Add a smoke assertion in `scratch/smoke_app.py` (or a small unit test) that constructs an audit with `flip_survives=False, off_features=()` and asserts `_cascade`'s chosen branch is the non-survival one (extract the branch decision into a testable pure helper, e.g. `cascade_state(audit, frame) -> Literal["breaks","no_survive","survives"]`).
